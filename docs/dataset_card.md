# 1. 데이터셋 개요

본 프로젝트는 초기 단계에서 분류(Classification)와 캡셔닝(Image Captioning) 실험에 동일한 데이터셋(raw-20260509-v1)을 사용하였다. 그러나 실험 과정에서 다음과 같은 문제가 확인되었다.

- 분류 모델: 중복 이미지, 깨진 이미지, 라벨 오류 가능 이미지로 인해 과적합 경향 발생
- 캡셔닝 모델: 생성된 캡션 품질이 낮고, 객체 중심 이미지가 문장 생성에 적합하지 않음

또한 분류 모델과 캡셔닝 모델이 요구하는 데이터 특성이 다르다고 판단하였다. 이에 따라 데이터셋을 다음과 같이 분리하였다.

### 분류 데이터셋

- raw-20260509-v1 (초기 실험)
- cls_raw-20260525-v2 (최종 분류 실험)

### 캡셔닝 데이터셋

- raw-20260509-v1 (초기 실험)
- COCO Caption Dataset (최종 캡셔닝 실험)

### 2.3 데이터셋 출처와 수집 비율

이미지는 Hugging Face, Kaggle, 웹 크롤링(Unsplash) 기반 수집 방식을 활용하여 구성하였다.

Roboflow Universe는 저작권 문제로 최종 수집 대상에서 제외하였다.

| 수집 출처 | 목표 비율 | 클래스당 목표 이미지 수 | 사용 여부 |
| --- | --- | --- | --- |
| Hugging Face | 약 27% | 60장 | 사용 |
| Kaggle | 약 27% | 60장 | 사용 |
| Roboflow Universe | 0% | 0장 | 제외 |
| Unsplash | 약 45% | 100장 | 사용 |

수집 기준은 클래스당 약 200장을 목표로 하였으며, 출처별 기본 수집 비율은 Hugging Face 60장, Kaggle 60장, Unsplash 100장으로 설계하였다.

다만 일부 클래스는 특정 출처에서 충분한 이미지를 확보하기 어려웠기 때문에, 클래스별 상황에 따라 Hugging Face와 Kaggle의 수집 수량이 조정되었다. 예를 들어 일부 동물, 꽃, 패션 클래스는 특정 출처에서 부족한 이미지를 다른 출처로 보완하였다.

최종 데이터셋은 클래스별로 약 187장부터 220장 사이의 이미지를 포함하며, 전체적으로 클래스당 약 200장 수준을 유지하였다.

### 해상도 기준

초기 데이터 수집 계획에서는 모든 이미지를 최소 256px 이상으로 확보하는 것을 목표로 하였다.

그러나 일부 Kaggle 데이터셋에서 256px 미만 이미지를 다수 확인하였고, 데이터 수량 확보를 위해 최소 기준을 128px 이상으로 완화하였다.

초기 데이터셋(raw-20260509-v1)에는 총 11,000장 중 1,383장의 이미지가 128~255px 해상도에 해당하였다.

이후 데이터셋 정제 과정에서 깨진 이미지, 중복 이미지, 라벨 오류 가능 이미지 등을 제거하였으나, 최종 데이터셋(cls_raw-20260525-v2)에도 1,351장의 128~255px 이미지가 포함되어 있다.

이는 전체 데이터의 약 13.3%에 해당하며, 데이터 수량 확보와 클래스 균형 유지를 위해 유지하였다.

### 2.5 Train / Validation / Test 분할

전체 데이터는 클래스별로 Train, Validation, Test로 분할하였다.

| 구분 | 비율 | 사용 목적 |
| --- | --- | --- |
| Train | 70% | 모델 학습 |
| Validation | 15% | 학습 중 성능 검증 및 best model 선정 |
| Test | 15% | 최종 모델 성능 평가 |

분할 방식은 랜덤 분할이 아니라, 클래스별 이미지 파일명을 정렬한 뒤 앞에서부터 순차적으로 나누는 방식을 사용하였다. 각 클래스 내부에서 독립적으로 분할을 수행하였다.

---

### 2.6 전처리 및 정제 과정

초기 수집 데이터에는 깨진 이미지, 중복 이미지, 클래스와 맞지 않는 이미지, 해상도가 낮은 이미지가 포함됐다. 따라서 최종 학습 데이터셋을 구성하기 전에 다음과 같은 정제 과정을 수행하였다.

- 깨진 이미지 제거
- 중복 이미지 제거
- `.jpg`, `.jpeg` 이외 확장자 제외
- 클래스명과 실제 이미지 내용이 맞지 않는 이미지 제거
- 사람이 보기에 클래스 구분이 어려운 이미지 검토
- 파일명 규칙에 맞지 않는 이미지명 수정
- 클래스별 이미지 수가 부족한 경우 추가 수집

정제 과정 이후 데이터셋 품질이 개선되었으며, validation loss 감소와 accuracy, macro-F1 향상을 통해 데이터 품질이 이미지 분류 성능에 큰 영향을 준다는 점을 확인하였다.

---

### 2.7 데이터 증강

데이터 증강은 원본 데이터셋 자체에는 포함하지 않는다. 모델 학습 단계에서는 필요에 따라 train 데이터에만 augmentation을 적용할 수 있다.

| 증강 기법 | 목적 |
| --- | --- |
| RandomResizedCrop | 이미지 크기와 위치 변화에 대한 일반화 |
| RandomHorizontalFlip | 좌우 반전 상황에 대한 일반화 |
| ColorJitter | 밝기, 색상, 대비 변화에 대한 강건성 확보 |
| RandomRotation | 촬영 각도 변화에 대한 대응 |

Validation과 Test 데이터에는 augmentation을 적용하지 않는다.
이는 모델의 실제 일반화 성능을 공정하게 평가하기 위해서이다.

### 2.8 데이터셋 한계

1. **일부 클래스는 시각적으로 유사하다.**
    
    예를 들어 음식 클래스나 꽃 클래스는 형태와 색상이 비슷한 경우가 있어 모델이 혼동할 가능성이 있다.
    
2. **클래스별 이미지 수가 완전히 동일하지 않다.**
    
    클래스당 약 200장을 목표로 수집했지만, 최종 데이터셋에서는 일부 클래스가 200장보다 적거나 많다.
    
    예를 들어 일부 클래스는 187장 수준이고, 일부 클래스는 220장 수준까지 포함되어 있다.
    
3. **수집 출처별 이미지 스타일이 다를 수 있다.**
    
    Hugging Face, Kaggle, 웹 크롤링 이미지는 촬영 방식, 배경, 해상도, 구도 등이 다를 수 있다.
    
    이 차이는 모델이 클래스의 본질적인 특징이 아니라 특정 출처의 이미지 스타일을 학습하는 원인이 될 수 있다.
    
4. **순차 분할 방식의 편향 가능성이 있다.**
    
    파일명을 정렬한 뒤 앞에서부터 train, validation, test로 나누기 때문에, 파일명이 수집 출처나 수집 순서를 반영하는 경우 특정 출처의 이미지가 한 split에 몰릴 수 있다.
